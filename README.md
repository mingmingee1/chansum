# Chansum

유튜브·웹 본문·텍스트 파일을 근거가 연결된 요약과 인포그래픽, A4 PDF로 정리하는 개인용 로컬 웹앱입니다. FastAPI와 SQLite를 사용하며 서버는 `127.0.0.1`에만 바인딩합니다. 외부 배포나 브라우저 저장소 기반 라이브러리는 사용하지 않습니다.

## Windows에서 시작

1. **64비트 Python 3.12**를 설치합니다. Python 3.11~3.14를 지원합니다.
2. 이 폴더의 **`install.bat`을 더블클릭**합니다. 최초 한 번 의존성과 PDF 출력용 Chromium을 설치합니다. Python이 없으면 다운로드 페이지를 엽니다.
3. **`start.bat`을 더블클릭**합니다. 서버를 시작하고 기본 브라우저를 엽니다. 이미 같은 데이터 위치의 Chansum이 실행 중이면 그 서버를 사용합니다.
4. 브라우저에서 **설정 및 백업 → 요약 엔진**을 선택하고 **실제 연결 테스트**를 누릅니다. 연결되지 않은 상태에서는 원문 수집 후 요약 실패를 표시하며 가짜 요약을 만들지 않습니다.
5. **새 자료 추가**에서 URL을 줄바꿈으로 붙여 넣거나 TXT·SRT·VTT·HTML 파일을 선택합니다. 링크 입력에 명령어를 사용할 필요가 없습니다.

실행 창을 닫거나 Ctrl+C를 누르면 서버가 종료됩니다. 브라우저 탭만 닫으면 서버와 작업은 계속 실행됩니다. 다음 실행에서 진행 중이던 작업을 식별하고 저장된 원문·분할 캐시부터 재개합니다. 설치 오류는 설치 창에 표시되며 창을 닫기 전에 확인할 수 있습니다.

## AI 연결

아래 어댑터를 구현했습니다. 실제 인증이나 모델 설치는 해당 사용자의 계정/PC 설정이 필요합니다. 자료 본문은 선택한 AI에 전달됩니다. 설정과 다운로드만으로 AI를 호출하지 않습니다.

| 방식 | 준비 | 브라우저 설정 |
| --- | --- | --- |
| Codex CLI | Codex CLI 0.163.0, ChatGPT 로그인. Node.js가 있으면 설치 스크립트에서 선택적으로 로컬 설치 | `Codex CLI` 선택 → `Codex 로그인` → 브라우저 로그인 → 실제 연결 테스트. 모델을 비우면 CLI 기본 모델 사용 |
| OpenAI 호환 API | 구조화 JSON 출력(`json_schema`)을 지원하는 서비스와 API 키 | 엔진·모델·API 기본 주소·키 입력. 주소 예: `https://api.openai.com/v1` |
| Ollama | PC에서 Ollama 서버 실행 및 32K 문맥을 지원하는 모델 설치 | `Ollama` 선택, `http://127.0.0.1:11434`, 설치한 모델 이름 입력. 입력을 최대 4,000자로 분할하고 32K 문맥을 명시적으로 요청해 기본 문맥의 묵시적 잘림을 방지 |

API 키는 서버의 별도 설정 폴더에 사용자 파일로 보관하고 브라우저에는 다시 반환하지 않습니다. 키 저장소는 OS 비밀 관리자가 아니라 사용자 전용 설정 파일입니다. Windows 사용자 프로필의 파일 접근 권한을 유지하세요. `CHANSUM_API_KEY` 환경 변수도 지원합니다. 키를 Git, 작업 로그, 백업에 넣지 않습니다. Codex 인증 파일은 Chansum이 복사하거나 관리하지 않습니다.

키는 입력한 서버의 origin(프로토콜·호스트·포트)에 연결합니다. 설정/백업의 서버 주소가 바뀌어도 기존 키를 다른 서버로 보내지 않습니다. 환경 변수 키는 기본적으로 OpenAI 공식 API에만 사용하며, 다른 서버에는 `CHANSUM_API_KEY_ORIGIN`도 지정해야 합니다. 앱 설정에서 직접 키를 입력하면 해당 서버에 자동 연결됩니다. 백업에 미완료 작업이 들어 있더라도 복원만으로 AI를 호출하지 않으며, 설정 확인 후 재시도할 수 있습니다. 정상 서버 재시작의 자동 재개와는 별개입니다.

라이브러리를 복원할 때 현재 PC의 AI 연결 설정과 비밀키는 유지합니다. 백업에 있는 서버 주소로 자동 전환하지 않습니다.

Codex는 별도 임시 폴더에서 실행하며 사용자 설정·MCP·셸·브라우저·멀티 에이전트 도구를 끄고 읽기 전용으로 호출합니다. 원문은 명령행 대신 표준 입력의 데이터 구간에 넣습니다. API/Ollama는 구조화 JSON을 요청합니다. 모든 엔진 결과는 다시 스키마와 근거 ID 검증을 통과해야 저장됩니다. ID 검증은 실제 문단의 존재를 확인하는 검사이며 문장 간 의미가 완전히 일치한다는 증명은 아닙니다.

## 화면과 기능

- **라이브러리:** 제목·확보한 썸네일·출처·저장일·상태, 제목/메모/URL 검색, 최신순/제목순, 유형·목록·즐겨찾기 필터, 여러 자료 선택.
- **새 자료:** URL 일괄 입력 및 TXT·SRT·VTT·HTML 업로드, 핵심/상세 모드, 목록 선택. 중복은 기존 항목 열기 또는 원문 갱신을 제안합니다. 휴지통 중복은 먼저 복원합니다.
- **목록:** 생성·이름 변경·삭제, 여러 목록에 추가/제거. 목록 삭제는 분류만 지웁니다. 원문·PDF는 자료마다 한 번 보관합니다.
- **상세:** 요약·인포그래픽·PDF·원문 탭, 근거를 클릭해 보관 문단 확인, 유튜브 시점 링크, PNG/PDF/SVG/HTML/JSON/원문 다운로드 API, 제목·즐겨찾기·메모, 옵션 변경 및 재생성.
- **작업 현황:** 대기/수집/요약/출력/완료/부분 완료/실패, 실제 완료한 단계·분할 수, 오류 코드·이유, 재시도·취소. 브라우저와 독립적으로 DB·파일에 진행 상황을 저장합니다.
- **휴지통:** 목록 연결을 유지한 삭제·복원. 영구 삭제는 자료 이름과 원문·이미지·전체 결과·메모·작업 기록의 삭제 범위를 확인합니다. 작업 중 삭제해도 완료 콜백이 자료를 다시 만들지 않습니다.
- **잠긴 파일:** 영구 삭제한 파일이 다른 프로그램에서 사용 중이면 삭제 예약을 보관하고 작업 종료/다음 실행에서 정리합니다. 설정에서 남은 정리 개수를 확인할 수 있습니다. 삭제된 자료의 잔여 파일은 백업에 넣지 않습니다.
- **설정/백업:** 엔진 상태·실제 호출 테스트·데이터 경로 확인, SHA-256 검증이 포함된 ZIP 백업과 복원. 처리 중에는 백업·복원을 막고, 복원 전 데이터는 별도 폴더에 보존합니다.

## 사용자 데이터

기본 Windows 위치:

```text
%LOCALAPPDATA%\Chansum\data\
  library.sqlite3             자료·목록·메모·작업·공개 설정
  items\<자료 ID>\
    input\                    업로드한 원본 파일
    thumbnail.*               확보한 이미지
    runs\<작업 ID>\           단계별 원문·요약·SVG·HTML·PNG·PDF
  cache\                      검증된 분할 요약 캐시
  work\                       호출 임시 파일 (호출 후 제거)
%LOCALAPPDATA%\Chansum\config\
  credentials.json            API 키, 백업 제외
```

Linux 기본값은 `$XDG_DATA_HOME/chansum` 또는 `~/.local/share/chansum` 아래의 `data`, `config`입니다. `CHANSUM_DATA_DIR`와 `CHANSUM_CONFIG_DIR`로 각각 변경할 수 있습니다. 두 경로는 겹치면 안 됩니다. 서버를 먼저 종료하고 폴더 전체를 옮기거나 백업·복원을 이용하세요. DB 파일만 실행 중에 복사하지 마세요.

개발용 포트는 `CHANSUM_PORT` 또는 `run.py --port`로 변경할 수 있습니다. 기본 포트는 **9417**입니다. 실행 인자는 링크 입력용이 아닙니다. 사용자 데이터는 코드 폴더의 `.venv`·소스와 분리되어 업데이트 때 유지됩니다.

## 수집·요약·출력 방식

유튜브는 `youtube-transcript-api`로 구간 ID·시작·길이·텍스트·언어를 보관하고 가능한 메타데이터를 수집합니다. 자막 없음일 때만 필요에 따라 `yt-dlp`를 보완 사용합니다. 차단을 회피하거나 무한 재시도하지 않습니다. 웹은 Trafilatura로 본문·문단 ID·URL·수집 시각·확보 가능한 제목/작성자/게시일을 저장합니다. 로그인이 필요한 화면·빈 본문은 실패합니다. 동적 페이지를 자동 조작하는 수집은 구현하지 않았습니다. 브라우저에서 HTML/TXT로 저장해 가져올 수 있습니다.

Playwright/Chromium은 **페이지 수집이 아니라 인포그래픽·PDF 출력과 UI 검증**에 사용합니다. 외부 리소스를 불러오지 않는 내부 렌더링으로 한글 폰트와 KaTeX 수식을 조판합니다. SVG/HTML은 편집 가능한 원본이고 PNG는 1,200px 폭입니다. 첫 PDF 페이지는 핵심 인포그래픽, 다음 페이지들은 상세 요약·조건·예외·근거·출처입니다. 긴 내용은 페이지를 늘리고 인포그래픽은 일부 핵심만 표시합니다. 원문에 없는 통계·비율은 생성하지 않습니다.

긴 원문은 ID를 유지하며 문자 한도에 맞춰 분할합니다. 일부 구간 실패는 부분 완료로 표시하고 미처리 ID를 남깁니다. 전역 인증 오류는 나머지 구간에 반복 호출하지 않습니다. 원문 해시·엔진·모델 설정/CLI 버전 지문·프롬프트 버전·옵션을 캐시 키에 반영합니다. 모델을 명시하면 모델 변경 시 캐시가 분리됩니다. Codex 기본 모델을 서버 측에서 바꾼 경우에는 명시 모델을 지정해 새 캐시를 사용하는 것이 좋습니다.

각 실행은 별도 세대에 출력합니다. 성공한 뒤에만 현재 결과 포인터를 바꾸므로 수집·AI·수식·출력 실패가 기존 성공 결과를 덮어쓰지 않습니다. 실패 원문과 단계 기록도 남깁니다. 요약에 포함된 원문 지시는 데이터로 취급합니다. 원문/AI 텍스트는 HTML로 삽입하지 않고, 외부 링크는 HTTP/HTTPS로 제한합니다. 로컬 호스트 검사와 요청 토큰으로 다른 웹사이트의 변경 요청을 거부합니다.

## 개발·검증

```bash
uv sync --frozen --group dev
python run.py --no-browser
python -m pytest -q
```

`uv.lock`과 해시가 포함된 `requirements.lock.txt`에 전이 의존성까지 고정했습니다. Windows 설치는 `pip --require-hashes`를 사용합니다. [의존성·공식 문서 기록](docs/dependencies.md), [검증 기록](docs/validation.md), [작업·데이터 설계](docs/architecture.md)를 참고하세요.

브라우저 자동 검증은 `tests.ui_server`의 **테스트 전용** 엔진을 주입하여 실행합니다. 이 서버에는 테스트 배너가 표시되고 결과 JSON·PDF에 실제 AI 요약이 아님을 표시합니다. `run.py`는 이 엔진을 불러오지 않습니다. `tests/ui_workflow.py`, `tests/ui_restore_check.py`에 검증 절차를 보관했습니다. 실제 AI/사이트 연결 결과는 별도로 기록합니다.
