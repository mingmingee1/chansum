# 작업과 데이터 설계

`items`는 원문 정체성(정규화 URL 또는 파일 해시)당 하나입니다. `memberships`의 다대다 연결로 여러 목록에 넣습니다. 목록 삭제는 연결만 지웁니다. `deleted_at`이 휴지통 상태를 나타내며 연결은 그대로 유지됩니다. 영구 삭제할 때만 자료 행, 관련 작업·연결, 자료별 파일 트리를 지웁니다.

`jobs`에 옵션·공개 엔진 설정·단계·작업량·분할 결과·캐시 키·오류·재개 횟수를 기록합니다. 단일 서버의 별도 작업 스레드가 대기 작업을 처리합니다. ASGI 이벤트 루프에서 AI·파일 추출·브라우저 렌더링을 수행하지 않습니다. SQLite는 WAL, 외래 키, busy timeout을 사용합니다. FastAPI의 요청 단위 백그라운드 태스크에 작업의 생명주기를 의존하지 않습니다.

새 자료와 최초 작업은 동일한 DB 트랜잭션으로 저장합니다. 입력 저장·큐 생성이 실패하면 자료만 대기 상태로 남지 않게 롤백합니다. 영구 삭제는 DB 커밋 전 삭제 예약 ID를 파일에 남기고, 잠긴 파일은 작업 종료 또는 다음 실행에서 재시도합니다. 실제 DB에 같은 ID가 남아 있으면 보호합니다. 백업은 DB가 참조하는 자료 폴더만 포함하므로 삭제한 자료의 잔여 파일을 가져오지 않습니다. 남은 삭제가 있으면 설정에 표시하며 복원은 정리가 끝날 때까지 거부합니다.

작업 재개 시 진행 중 상태는 `interrupted`로 식별합니다. 수집이 끝난 원문 경로와 검증된 분할 캐시를 재사용합니다. 모델 호출 직후 중단되어 결과를 저장하지 못했다면 그 구간은 다시 호출될 수 있습니다. 분산 결제의 exactly-once를 보장하지 않습니다.

작업 순서는 `queued → collecting → summarizing → editing → rendering → complete/partial`입니다. `editing`도 재시작·취소·삭제·백업 잠금의 활성 작업에 포함합니다. `claims.json`에 추출 항목과 원문 인용을, `editing.json`에 완료한 구성 배치와 캐시 키를, `report.json`에 전체 구성 결과를 저장합니다. 0.3의 분할 추출 프롬프트는 `chansum-evidence-3`, 보고서 구성 버전은 `chansum-report-3`이며 이전 캐시와 분리합니다.

`report.py`는 원문 ID가 있는 추출 항목에 고유 항목 ID를 부여합니다. 종류와 정규화한 문장이 정확히 같은 항목만 합치고 근거 ID를 모읍니다. 편집 엔진은 제목·전체 요지·주제·그룹·주장·연결된 설명·시각화 구조를 반환합니다. 프로그램은 존재하는 항목 ID만 사용하고 본문에 모든 항목을 정확히 한 번 배치했는지 검사합니다. 의미가 비슷하다는 이유만으로 항목을 삭제하지 않습니다.

0.3에서는 각 주제에 그림용 `digest`, 각 주장에 `explanation`을 요구합니다. 편집한 설명의 근거에는 해당 주장의 ID가 포함되어야 하며 비교·이유를 위해 다른 유효한 항목도 참조할 수 있습니다. 화면·PDF는 `narrative`를 표시하고 최초 추출 문장은 `item`에 보존합니다. 관련 조건·예외와 원문도 별도로 남습니다. 주제별 요약의 ID는 그 주제에 배치한 항목인지 검사합니다. 인포그래픽은 전체 주제의 digest와 주요 도식을 함께 렌더링하므로 특정 도식에 포함되지 않은 주제도 나타납니다.

핵심/상세 모드를 편집 호출까지 전달하며 새 자료의 기본값은 상세입니다. 단위별 원문 인용은 최대 3개·각 1,000자로 전달합니다. 긴 문서의 상위 구성에는 전체 하위 트리를 로컬에 보존하면서 제목·핵심 문장·주제별 digest·주요 조건과 한도 내 overview를 전달합니다. 상위 단계의 인용은 선정한 2개·각 300자로 제한하여 다음 단계에서 여러 개요를 실제로 합칠 수 있게 합니다. 구성 입력 예산은 6,000~16,000자이고, 한 배치의 항목은 최대 24개입니다. 입력·출력 한도 때문에 원문의 모든 글자가 매 편집 호출에 전달되는 것은 아닙니다.

긴 입력은 한도에 맞춘 구성 배치의 개요·주제별 요지·주요 조건·선정한 원문 인용을 다음 단계에 전달합니다. 완전한 하위 본문은 로컬 트리에 보존하여 추상화 과정에서 버리지 않습니다. 구성 캐시는 원문 해시·구성 버전·입력 항목과 인용·엔진 설정·옵션으로 나누고 재사용할 때 다시 검사합니다. 구성 실패 또는 출력 실패는 기존 결과 포인터를 바꾸지 않습니다.

`design.py`는 검증된 동일 보고서 데이터에서 4종 SVG와 HTML 본문을 만듭니다. 차트는 실제 원문의 값·단위·인용 위치 및 주변의 일부 제한 표현을 검사하고, 비교표의 열 수와 흐름도의 연결 순서도 검사합니다. ID·배치·형식 검사는 원문 사실의 완전한 추출이나 설명의 의미적 정확성까지 보장하지 않습니다. 실제 엔진의 편집 품질은 별도 검증 대상입니다. 이전 형식의 저장 결과도 계속 열 수 있습니다.

새 작업마다 `runs/<작업 ID>`를 만듭니다. 성공한 원문과 검증된 요약을 이용해 SVG/HTML/PNG/PDF를 생성한 뒤 DB의 `result_path`, `source_path`를 한 트랜잭션에서 갱신합니다. 그 전까지 이전 결과가 현재 결과입니다. 실패해도 기존 세대를 바꾸지 않습니다. 부분 요약은 누락된 분할·구간 ID를 명시한 결과를 생성합니다.

작업 완료 갱신은 `WHERE id=? AND active_job=? AND deleted_at IS NULL`을 조건으로 합니다. 처리 중 삭제는 활성 작업을 취소하고 `active_job`을 비웁니다. 작업 스레드는 단계별로 상태를 확인하며 행을 재삽입하지 않습니다. 영구 삭제와 작업 종료가 엇갈려 만들어진 파일은 스레드 종료 시 추가 정리합니다.

백업·복원은 DB 유지보수 잠금을 사용합니다. 큐/진행 중 작업이나 종료되지 않은 작업 스레드가 있으면 거부합니다. SQLite backup API의 스냅샷을 사용하고, ZIP에 쓴 동일 바이트로 SHA-256 manifest를 만듭니다. 복원은 별도 staging 디렉터리에서 크기·경로·파일 해시·DB 구조·외래 키·원문/요약 파일 존재를 확인한 뒤 교체합니다. 기존 데이터 디렉터리를 별도로 보존하며 비밀키 폴더는 포함하지 않습니다.

사용자 데이터에는 원문 내용 자체가 들어갑니다. 외부 AI를 선택하면 원문 분할 내용이 해당 서비스에 전달됩니다. UI는 텍스트 DOM API와 안전한 KaTeX 설정을 사용하며 외부 코드나 원본 HTML을 실행하지 않습니다. 출력 브라우저의 모든 네트워크 요청은 중간에 가로채고 앱의 정적 자산·생성 문서만 제공합니다. 외부 사이트의 스크립트·이미지를 출력 과정에서 실행하거나 불러오지 않습니다.

복원한 DB의 자료·목록·작업 ID는 32자리 UUID hex 형식인지 검사합니다. 정상 백업은 미완료 작업을 포함하지 않지만, 미완료 작업을 가져온 경우 취소 상태로 식별하고 명시적인 재시도를 기다립니다. 복원만으로 자격 증명을 사용하는 AI 요청을 보내지 않습니다. API 키는 별도 비밀키 파일의 origin에 연결하고 서버 주소가 달라지면 전달하지 않습니다. 정상 실행 중 서버 종료로 중단된 작업의 자동 재개는 유지합니다.

라이브러리 복원은 현재 장치의 AI 연결 설정도 유지합니다. 자료·목록·메모·작업 이력·원문·결과물만 복원하며 새로 가져온 백업의 주소로 미래 입력을 전송하도록 설정을 바꾸지 않습니다.
