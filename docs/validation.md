# 검증 기록

검증 환경은 Linux, Python 3.12.14, 시스템 Chromium입니다. Windows 실기기는 사용할 수 없어 `.bat` 실행과 브라우저 자동 열기는 Windows에서 추가 확인이 필요합니다.

## 실행한 검증

- `python install.py`: 해시가 포함된 잠금 파일로 설치/재설치 성공. 이미 있는 시스템 Chromium을 사용했습니다. Windows의 Chromium 다운로드 분기는 실행하지 않았습니다.
- `python -m pytest -q --junitxml=test-results/pytest.xml`: **0.2.0에서 76개 통과, 실패·건너뜀 0개**. Starlette 테스트 클라이언트의 향후 httpx2 전환 안내 경고 1개가 있습니다. 앱 실행 실패가 아닙니다. `uv lock --check --offline`, `uv pip check`, 프런트엔드 JS 구문 검사도 통과했습니다.
- `run.py --no-browser`: 0.2.0 로컬 서버 기동 및 `/api/health`, 화면 응답 확인. 같은 데이터 위치로 다시 실행했을 때 기존 서버를 사용하고 종료 코드 0을 반환했습니다.
- `tests/ui_workflow.py`: 0.2.0 브라우저에서 목록 생성 → TXT 추가 → 작업 상태 → 상세/근거·새 목차 확인 → PNG/PDF 다운로드 → 제목·즐겨찾기·메모 변경 → 캐시 재생성 → 여러 목록 분류 → 검색·유형·정렬 → 휴지통 이동·복원 → 백업 다운로드 확인.
- `tests/ui_restore_check.py`: 서버 재시작 후 제목·메모·목록·요약·원문 유지, 별도 테스트 데이터 위치로 UI 복원, 해당 백업 시점의 원문 해시·요약 JSON·PDF 바이트 동일 확인.
- `CHANSUM_INTERRUPT_STAGE=editing python -m tests.ui_interruption`: **보고서 구성 중 상태를 확인한 뒤 실제 서버 프로세스를 강제 종료**하고 재시작했습니다. 중단 횟수 1회, 원문 경로 유지, 분할 캐시 재사용, 자동 재개 및 완료를 브라우저에서 확인했습니다. 이전 버전에서는 요약 중 강제 종료도 검증했습니다.
- `tests/ui_additional.py` (기존 버전 검증): 중복 자료를 새 작업 없이 열기, 목록 생성·이름 변경·삭제 후 자료 유지, 원문/요약의 `<script>`·이벤트 문자열이 실행되지 않음, 자료 추가 후 새로고침에도 작업 유지, 범위 확인 후 영구 삭제, 정확한 새 작업 ID의 캐시 완료 확인.
- `tests/ui_notes_restart.py` (기존 버전 검증): 작업 완료 때 메모에 포커스가 있어도 내용을 유지하고, 포커스를 옮긴 뒤 결과를 갱신합니다. 서버 재시작 후 원래 페이지의 오래된 요청 토큰을 자동 갱신해 메모를 저장하는 것도 확인했습니다.

0.2에서 추가한 검증은 구성 단계의 항목 누락·중복·없는 ID 거부, 조건·예외 연결, 긴 문서의 마지막 예외 및 전체 본문 트리 보존, 다단계 구성 캐시 재사용, 완료한 편집 배치부터 재개, 구성 실패 시 이전 PDF 보존, 구성 중 삭제 시 자료 재생 방지입니다. API 어댑터가 새 스키마와 실제 원문 인용을 전달하는 것도 테스트 대역으로 확인했습니다.

차트 검증 회귀에는 원문의 숫자·단위 불일치, 없는 인용, 부분 인용으로 숨긴 근사·상하한, 하이픈/en dash 범위, 뒤따르는 범위, 다른 숫자의 일부, 복합 단위의 일부, 명시적으로 부정된 값이 포함됩니다. `계약`의 `약`을 근사 표현으로 오인하는 경우도 수정했습니다. 이 검사가 모든 자연어 의미를 판정하는 것은 아닙니다.

자동 테스트는 긴 단일 문단의 문자 손실 없는 분할, SRT/VTT 시간, HTML 본문 추출, 로그인·빈 본문 거부, 없는 근거 ID 거부, 부분 완료와 누락 ID, 일시 오류만 최대 2회 시도, 차단 즉시 종료, 수집 실패 기록·재시도, AI/출력 재생성 실패 때 이전 결과 보존, 처리 중 삭제 시 재생 방지, 다중 선택·검색·필터·정렬, 복원 경로 공격 거부, CSRF/호스트 검사, 비밀키 백업 제외, Windows npm Codex 래퍼의 셸 없는 인자 구성을 검사합니다.

복원 DB에 경로 이동을 유발하는 자료 ID를 넣은 경우 거부, 복원한 미완료 작업의 AI 자동 호출 방지, API 키의 원래 서버 origin 제한, 출력 출처의 실행 가능한 URL 차단도 검사했습니다.

원문 갱신 수집이 실패하면 재시도 때 수집을 다시 수행하고, 갱신 원문 확보 후 AI가 실패했다면 재시도 때 그 작업의 확보된 원문을 재사용합니다. 두 경우 모두 이전 성공 결과는 새 작업 성공 전까지 유지되는 것을 검사했습니다.

자료와 첫 작업의 원자적 저장, 잠긴 파일의 영구 삭제 예약·재시도, 삭제된 자료의 잔여 파일이 백업에 포함되지 않음, 삭제 예약만 남고 DB 삭제가 커밋되지 않은 경우 실제 자료를 보호하는 것도 검사했습니다. Windows 파일 잠금은 모의한 테스트이며 Windows 실기기 확인을 대신하지 않습니다.

라이브러리 복원이 현재 PC의 AI 서버 주소를 바꾸지 않고, 지원하지 않는 Windows 배치 CLI 래퍼를 셸로 우회 실행하지 않는 것도 확인했습니다.

CLI 시간 초과 시 앱이 만든 프로세스 트리를 종료합니다. POSIX에서는 실제 자식 프로세스를 만든 테스트로 종료를 확인했습니다. Windows의 `taskkill /T` 분기는 실기기에서 확인해야 합니다.

## 출력물

0.2의 UI 흐름에서 생성한 PDF는 **A4 세로 5페이지**입니다. 전 페이지 렌더링, 한글과 KaTeX 수식 폰트 포함, 한국어 텍스트 검색·선택, 클릭 가능한 근거 링크, 페이지 밖으로 나간 텍스트 없음을 확인했습니다. SVG 배치와 A4 수식 폭을 넘으면 결과를 성공으로 저장하지 않는 검사도 있습니다. 새 주제 요약의 넓은 수식 거부, 분해형 한글 정규화, 3열 비교표와 여러 근거 링크는 실제 Chromium 출력으로 검사했습니다.

`test-results/sample-infographic.png`, `sample-report.pdf`, `sample-backup.zip` 및 UI 스크린샷을 생성했습니다. 출력 샘플은 **명확하게 표시한 AI 테스트 대역**으로 제작했습니다. 실제 AI가 작성한 요약 예시로 제시하지 않습니다. 테스트 대역은 원문을 추출해서 그대로 반환하며 기본 앱에는 연결되지 않습니다.

별도로 `python -m tests.report_examples`로 비교표·관계도·흐름도·차트 4종 예시를 만들었습니다. 각 PDF는 5페이지로 **총 20페이지를 렌더링하고 4개 PNG 및 전 페이지 이미지에서 글자·겹침·잘림·조건 문단 배치를 확인**했습니다. 표지 근거 링크는 종류별 8~16개입니다. 아스트라 검토도 거쳤으며 지적된 차트 검증 허점은 회귀 테스트와 함께 수정했습니다.

이 4종은 `tests/report_examples.py`의 **별도로 작성한 가상 예문과 수동 보고서 계획**으로 만들었습니다. 새 구조의 표현·출력 검증이며 실제 AI의 편집 품질을 검증한 결과가 아닙니다. 사용자 첨부 PDF는 배포물에 넣지 않았습니다. 다운로드 폴더의 PDF·PNG는 비교형 예시이며, 예시의 근거 링크는 검증용 자료 ID를 사용하므로 실제 사용자 라이브러리의 항목으로 연결되지 않습니다.

## 실제 외부 연결

| 대상 | 실제 결과 |
| --- | --- |
| 공개 MDN HTML (`raw.githubusercontent.com/mdn/beginner-html-site/gh-pages/index.html`) | Trafilatura로 제목 `Mozilla is cool`, 3개 문단, 본문 416자 수집 성공 |
| Python 공식 튜토리얼 웹페이지 | 현재 네트워크 정책/접근 차단, `blocked`로 구분 |
| 공개 유튜브 `jNQXAC9IVRw` | 현재 네트워크에서 자막 요청 차단, `blocked`로 구분. 실제 자막 수집 성공은 미검증 |
| Codex CLI | 기존 ChatGPT 로그인 확인. 일반 실행의 읽기 전용 초기화 제한을 확인하고, 허용된 초기화 경로에서도 실제 요청이 180초 내 완료되지 않음. **실제 AI 요약 성공은 미검증** |
| OpenAI 호환 API/Ollama | 요청·인증 헤더·JSON 스키마·근거 검증 프로토콜 테스트 통과. 실제 계정/모델은 제공되지 않아 실제 서버 호출 미검증 |

추가 HTTPS 진단에서 현재 프록시가 `chatgpt.com`과 `api.openai.com`을 거부함을 확인했습니다. Codex용 `chatgpt.com` 허용안은 클라우드 환경 설정 초안에 저장했지만 현재 실행 환경에 적용되거나 게시된 상태가 아닙니다. 환경 설정에서 검토·저장 후 Publish가 필요합니다. 직접 OpenAI API를 선택하면 `api.openai.com` 허용도 별도로 필요합니다. Windows PC의 일반 네트워크 설정과 이 클라우드 프록시는 별개입니다.

AI가 없거나 실패하면 원문과 실패 작업을 남깁니다. 테스트 대역으로 자동 전환하지 않습니다. 실제 사용할 방식은 앱 설정에서 선택하고 인증/모델을 준비한 뒤 실제 연결 테스트가 성공해야 합니다.

## 남은 제한

Windows에서 Python 설치, 더블클릭 실행, 자동 브라우저 열기, Codex 브라우저 로그인, Playwright Chromium 다운로드를 실기기로 확인해야 합니다. 동적/로그인 웹페이지 수집은 파일 입력으로 대체합니다. yt-dlp 보완 경로는 실제 유튜브 차단 때문에 검증하지 못했습니다. 영상 장면 캡처·슬라이드 삽입은 미구현입니다. 실제 AI가 긴 원문을 새 계층 구조로 적절히 편집하는 품질도 미검증입니다. 파일은 한 개 12MB, 백업·복원은 압축 전 합계 512MB로 제한합니다. 매우 넓거나 KaTeX가 지원하지 않는 수식은 출력 실패로 남기고 기존 결과를 보존합니다. 근거 ID 검사는 요약 문장 전체의 의미적 정확성을 증명하지 않습니다.

개별 검증의 상세 결과는 `test-results/pytest.xml`, `pdf-check.json`, `restart-restore-check.json`, `interruption-check.json`, `additional-ui-check.json`, `notes-restart-check.json`, `live-collection.json`, `live-engine.json`, `ai-network-check.json`에 있습니다. 이 폴더는 개발 검증 산출물이며 사용자 라이브러리와 별도입니다.

0.2의 보고서 구성 중단 기록은 `test-results/editing-interruption-check.json`, 4종 출력물과 전 페이지 이미지는 `test-results/report-v2/<종류>/`에 있습니다. 이전 버전의 결과는 `test-results/before-report-v2/`에 따로 보존했습니다.
